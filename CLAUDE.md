## Project Purpose

Daily ETL pipeline that downloads public datasets from the Chilean CMF (Comisión para el Mercado Financiero) and loads them into a PostgreSQL database. Both the app and the database run on Fly.io.

## Stack

- **Language**: Python 3.12
- **Database**: PostgreSQL (Fly.io managed `fly pg` cluster)
- **HTTP**: `httpx` (async downloads)
- **Data parsing**: `pandas`
- **ORM / query builder**: `SQLAlchemy` (async engine)
- **Migrations**: `Alembic`
- **Scheduling**: `APScheduler` (runs inside the process)
- **API (optional, future)**: FastAPI
- **Deployment**: Fly.io (`fly.toml`)

## Architecture

```
cmf_downloader/
├── downloaders/      # One module per CMF dataset; each implements a common interface
├── models/           # SQLAlchemy ORM models (one file per logical domain)
├── db/               # Engine setup, session factory, Alembic env
├── scheduler.py      # APScheduler wiring — registers all downloader jobs
└── main.py           # Entrypoint: starts scheduler (and FastAPI app if API is added)

alembic/              # Migration scripts generated by Alembic
fly.toml              # Fly.io app config
Dockerfile
```

### Downloader interface

Each downloader in `downloaders/` should expose a single async function:

```python
async def run(session: AsyncSession) -> None: ...
```

`scheduler.py` imports all downloaders and registers them with APScheduler. Adding a new CMF dataset means adding a new module in `downloaders/` — no changes needed elsewhere.

### Database sessions

Sessions are created per-job run (not shared across jobs). Use `async with session_factory() as session` inside each `run()` function.

## Git Workflow

- Always develop on a feature branch, never directly on `main`.
- Branch naming: `feature/<short-description>` (e.g., `feature/cmf-fondos-downloader`).
- Commit when a feature or meaningful unit of work is complete — not mid-implementation.
- Push the branch and open a PR into `main` when the feature is ready.

## Common Commands

```bash
# Install dependencies
pip install -r requirements.txt

# Run migrations
alembic upgrade head

# Generate a new migration after model changes
alembic revision --autogenerate -m "description"

# Run the scheduler locally
python main.py

# Fly.io — deploy
fly deploy

# Fly.io — connect to production Postgres
fly pg connect -a <pg-app-name>

# Fly.io — tail logs
fly logs
```

## Environment Variables

| Variable | Description |
|---|---|
| `DATABASE_URL` | SQLAlchemy async DSN, e.g. `postgresql+asyncpg://user:pass@host/db` |
| `CMF_*` | Any auth tokens or config specific to a CMF endpoint |

Set locally via `.env` (loaded with `python-dotenv`). On Fly, set via `fly secrets set KEY=value`.

## Fly.io Notes

- The app runs as a single Fly Machine (always-on) with APScheduler inside.
- PostgreSQL lives in a separate `fly pg` app; connect via the private Fly network (`<pg-app>.internal`).
- Persistent volumes are not required — all state lives in Postgres.
